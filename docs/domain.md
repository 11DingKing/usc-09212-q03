# 跨境算法合规窗领域约定

## 设计原则

- 事件时间与接收时间分离；所有业务身份由调用方提供稳定标识。
- 发布档案、规则包、判定记录均为**只追加的版本化档案**，旧批准永不被追溯改写。
- 判定输入锁定到「发布修订号 + 规则包版本」，二者任一实质变化即产生新的评估任务。
- 所有判定结论以 SHA-256 **哈希链**锚定，任一条旧记录被改动都可在 `/audit/chain` 复核发现。

## 核心实体

### 发布档案 Release

一份可版本化档案包含：模型版本（`model_version`）、数据类别（`data_categories`）、
用途（`purpose`）、部署地（`deployment_jurisdiction`）、供应商链（`vendor_chain`，
每项含名称与所在辖区），并可声明数据主体所在地、是否涉及未成年人、是否为高风险决策。

- `POST /releases` 创建修订号 1；`POST /releases/{id}/revisions` 追加新修订，旧修订保留。
- 适用辖区 = 部署地 ∪ 数据主体所在地；只有适用辖区的规则参与求值。
- 跨境（`cross_border`）在数据主体辖区与部署地不一致、或供应商位于其他辖区时成立。

### 规则包 Rule Package

- 规则按辖区组织，版本号一旦发布即不可变；同版本号内容必须一致，否则冲突拒绝。
- 规则条件（AND 组合）：数据类别、用途、部署地、主体辖区、供应商辖区、
  涉及未成年人、高风险决策、跨境。
- 命中规则产生一项**义务**，义务声明：风险级别、所需证据种类、必要签署角色、
  是否要求外部证明（证书 scope）。
- 发布新规则包后，系统对每个发布最新修订计算「义务指纹」，仅当指纹变化
  （命中集合或义务内容变化）才把该发布自动入队重评；仅版本号变化不影响义务时不打扰发布。

### 判定 Assessment

- 评估队列中的任务对锁定的修订与规则版本求值，输出：
  - `decision`：`BLOCKED`（有证据/证明缺口）/ `PENDING_SIGNOFF`（等待必要角色）/
    `APPROVED` / `REJECTED` / `REQUIRES_REASSESSMENT`（输入已漂移）。
  - `obligations`：每条命中义务及状态（`OUTSTANDING`/`WAIVED`）。
  - `evidence_gaps`：具体缺口，含义务 id、辖区、类型（evidence/certificate/waiver）、
    项目与原因（missing/expired/revoked/not_yet_valid/…）。
  - `decision_path`：可复核路径——辖区圈定 → 条件命中明细 → 证据解析 →
    豁免解析 → 哈希锚点 → 角色签署解析 → 实时闸门检查。

### 证据 / 外部证明

- 证据按种类登记到发布，可带有效期；种类覆盖某义务的全部所需证据即视为满足。
- 外部证明（证书）记录签发方、scope、有效期与撤销位，可绑定发布或作为辖区通用证明。
- **流量闸门实时复核**：即使已批准，证书到期/撤销或豁免失效，`traffic_allowed`
  立即变为 false 并阻断新流量，同时安排复评。旧判定记录不被修改。

### 临时豁免 Waiver

豁免是四元组范围约束：发布 + 辖区 + 具体义务 + 起止期限，且必须写明范围说明。
过期或撤销后自动失效；不会泄漏到其他发布或其他义务。

### 签署 Signoff

- 义务声明必要角色集合；**并发签署不能跳过任何必要角色**，缺角色则保持
  `PENDING_SIGNOFF`，任一角色 `REJECT` 即 `REJECTED`。
- **利益冲突隔离**：审查者须登记关联机构；与发布供应商链关联者禁止签署。
- **职责隔离**：同一审查者不得在同一判定上兼任两个必要角色。
- 只能对该发布的**最新判定记录**签署；档案修订或规则漂移后旧签署目标关闭。

### 持久队列

- 评估任务持久化在 SQLite，状态 pending/running/done/failed，最多重试 3 次。
- 进程启动时把残留的 running 任务回收为 pending，重启后继续评估队列。

## 时间

统一使用 UTC、秒级 ISO8601（尾缀 `Z`）。测试用 `FixedClock` 推进时间，
以确定性地验证证书/豁免到期行为。
