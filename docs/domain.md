# 跨境算法合规窗领域约定

服务采用事件时间与接收时间分离的记录方式：审计条目同时保留调用方提供的
`occurred_at`（事件时间）与服务端写入的 `recorded_at`（接收时间）。
所有业务身份由调用方提供的稳定标识表示，审计记录不得以覆盖方式修改。

## 核心概念

- **档案（profile）**：模型版本、数据类别、用途、数据出发地、部署地、供应商链
  与一个归属机构。每次登记生成递增版本，历史版本不可变。
- **规则集（ruleset）**：按法域（中国及东盟各国或 `ALL`）组织的判定规则，
  只追加新版本。规则包含匹配条件、严重级别（block/review）、义务、
  所需证据、所需外部证明与所需签署角色。
- **评估（evaluation）**：对某档案版本 × 某规则集版本的一次判定，输出
  APPROVED / CONDITIONAL / BLOCKED、义务清单、证据缺口与逐条规则的判定轨迹。
  评估经持久队列异步执行，重启后续跑。
- **签署（signature）**：按（评估， 角色）唯一；审查者须持有对应角色且
  与档案归属方、供应商链无利益冲突（含其申报的冲突机构）。
- **豁免（exemption）**：限期、限范围（规则/证据/义务）地覆盖特定缺口；
  到期自动失效，发布与流量准入时点均按当前时间重新核算。
- **外部证明（certificate）**：如出境安全评估证明，带有效期；过期即构成
  阻断级缺口并阻断新流量。
- **发布（release）**：发布记录不可变，状态由只追加的事件流派生
  （ACTIVE / DENIED / REASSESSMENT_PENDING / SUSPENDED）。
  规则更新只追加“待复评”事件并入队新评估，不追溯篡改旧批准。

## 不变式

1. 档案、规则集、评估结果、发布记录、审计流水一经写入不得修改。
2. 发布必须满足：当前规则集版本下评估完成、无未豁免缺口、必要角色签署齐备、
   所需外部证明在有效期内。
3. 新流量准入以发布当前事件状态与证明有效期为准，与历史批准无关。
